# Artisan's Material Board — Dalamud API 15

クラフターの製作対象を検索し、名前付きリストと必要素材を管理するプラグインです。

## 導入（開発プラグイン）

1. `ArtisansMaterialBoard-v1.0.0.1.zip` を任意の固定フォルダーへ展開します。
2. Dalamud設定の「試験的機能 / Experimental」にある「開発プラグインの場所 / Dev Plugin Locations」に、展開した `BuildLists.dll` の絶対パスを追加します。
3. 開発プラグイン一覧で Artisan's Material Board を読み込みます。
4. チャットコマンド `/buildlists` またはプラグイン一覧のUIボタンで開きます。

API 15 用です。ソースのビルドには .NET 10 SDK と API 15 の Dalamud 開発ライブラリが必要です。

## 操作

- **ホーム**: プラグイン説明、更新履歴、読込レシピ数、保存リスト数。
- **制作リスト**: 編集する保存済みリスト、または新規リストを選択し、画面上部でリスト名を設定します。アイテム名入力中に候補を表示。職と完成数で同名レシピを区別できます。候補選択→完成品の個数→Add。追加済みの完成品は別レシピも含め候補から除外し、削除すると候補に戻ります。各対象の個数変更・削除も可能です。
- **Save**: 入力済みの名前で新規保存、または選択したリストを同じIDのまま上書きします。空白名・別リストとの同名は不可。下書きと保存済み内容は独立し、Saveまで保存済み内容は変更されません。下書きと編集中のリストIDも設定に保存します。未保存の変更がある状態で別リストに切り替える場合は破棄確認が表示されます。
- **リスト削除**: 制作リストまたは素材リストで選択中のリストを削除できます。確認後に削除し、そのリストに紐づく編集中の下書きもクリアします。削除の永続化に失敗した場合は内容を復元します。
- **素材リスト**: 保存リストを検索して選択。中間素材から原材料まで全階層の必要素材をアイテムIDで合算し、バッグとリテイナー記録、合計所持数／必要数、不足数を表示。「製作の内訳」で階層を展開できます。「このリストを編集」で編集画面に移動します。
- **TSV出力**: 素材リストの合算表を、Excelでも開きやすいUTF-8 BOM付きTSVに出力します。出力列は「素材名」「手持ち/全体必要数」「バッグ」「リテイナー記録」「全体不足」の5列です。素材リストと同じ親子順・共通素材の再表示・クリスタル類の末尾合算に従います。未取得の所持品は「未取得」です。ファイル名はリスト名＋日時＋識別子で、既存ファイルを上書きしません。
- **TSVの出力先設定**: 素材リストの設定欄で絶対パスを入力し「出力先を保存」を押します。初期値はWindows標準のダウンロードフォルダーです。Windows側でフォルダーを移動している場合も現在の設定を取得します。「標準のダウンロードに戻す」で初期設定に戻せます。
- **ログ**: INFO、WARN、ERROR を全て表示。検索、コピー、末尾追従。検索文字の変更、候補選択、追加、削除、個数変更、保存、画面変更、データ更新、例外を記録します。描画フレームごとの同じ情報は記録しません。

## 数量の定義

完成品の個数から、1回で完成する個数を考慮して製作回数を切り上げます。同一レシピは個数をまとめてから切り上げます。
レシピに直接必要な素材とクリスタルに加え、中間素材の製作に必要な素材を再帰的に展開します。合算表・TSVでは、複数の親から必要となる共通中間素材をまとめてから、その素材の製作回数を切り上げます。
制作リストには製作対象アイテム・個数・製作回数を表示し、素材内訳は表示しません。
素材リストは「中間素材 → その基本素材 → 次の中間素材 → その基本素材」の順です。基本素材の名前は黄色と字下げで表示します。共通素材は各中間素材の下に再表示しますが、必要数・不足数はリスト全体の合算値で、重複行を足し合わせる必要はありません。TSVも画面の並び順に合わせます。
中間素材とその材料を両方表示します。すべての中間素材を自作する計画であり、所持済み中間素材は下位の必要数から差し引きません。階層表示は対象別の内訳、合算表・TSVはまとめ製作した数量です。
同じ中間素材に複数レシピがある場合は、レシピIDが最小のものを使用し、職名を階層表示に示します。循環参照や数量のオーバーフローは集計を中止し、画面とログに理由を表示します。製作操作の自動実行、製作可能条件の判定は含みません。

バッグは通常の所持品4ページとクリスタルです。NQ/HQは合算し、収集品は除外します。装備、アーマリーチェスト、チョコボかばん、マーケット出品物は含めません。

## リテイナー所持数

各リテイナーの所持品画面を開き、数秒待ってください。5ページとクリスタルが読み込まれ、同じリテイナーの内容が連続して安定したときに記録します。
所持品画面が閉じている間は前回取得の記録を使用します。未取得のリテイナーは含まれません。記録人数と最も古い取得日時を表示します。
記録はキャラクターのContent IDとリテイナーIDで分離し、別キャラクターの所持数と混ざらないようにしています。読み込み不能・ログアウト時のバッグ数は `?` と表示します。

リテイナー一覧を取得できた後は、現在の一覧に存在するリテイナーの記録だけを合算します。一覧未取得時は保存済み記録を使用します。未取得状態、画面レイアウトやゲーム更新による取得条件はゲーム内の確認対象です。初版の不足数は「取得済み記録を基準とした値」であり、全リテイナーのリアルタイム値ではありません。

## 保存とログ

Dalamudのプラグイン設定にリスト・下書き・編集中リストID・TSV出力先・キャラクター別リテイナー記録を保存します。既存の設定・保存リストを引き続き読み込めます。バージョンは1.0.0.1です。
プラグイン設定ディレクトリーの `BuildLists.log` にもログを書き出します。約5MBで `.1` にローテーションし、画面には直近3,000件を保持します。
ログには検索したアイテム名とリスト名が含まれます。ログ画面から実際のファイルパスを確認できます。

## ビルドと検証

```powershell
dotnet build BuildLists.csproj -c Release
dotnet run --project Tests/BuildLists.Tests.csproj -c Release
```

Dalamud.NET.Sdk 15.0.0 が標準の `%APPDATA%/XIVLauncher/addon/Hooks/dev` を参照します。別の配置では `DALAMUD_HOME` を指定してください。

この環境では API 15 の実ライブラリに対する Release ビルドを検証しました。ゲーム内へのロード、画面表示、レシピ検索、リテイナーの実データ取得は未検証です。
数量計算・再帰展開・親子順表示・共有素材の切り上げ・循環検出・編集/削除と失敗時復元・TSV実ファイル出力・Windowsダウンロードフォルダー取得を含む43項目のテストを通過しています。

## ゲーム内チェックリスト

1. `/buildlists` で4画面が表示され、日本語・サイズ変更・スクロールが正常なこと。
2. 1回で複数個できるレシピを選び、個数変更で素材数が切り上がること。
3. 異なる製作対象の共通素材が合算されること。
4. Save→再読込後もリストと下書きが残ること。
5. インベントリのNQ/HQ、クリスタルの実数を照合すること。
6. 各リテイナーを開いて、所持品画面の通常／拡大表示で記録人数と数量が更新されること。
7. リテイナーを素早く切り替えた場合、転送直後、ログアウト、別キャラクター切替でも誤った合算がないこと。
8. 各操作のINFO、記録方式のWARN、読込・保存障害のERRORがログ画面とファイルに出ること。
9. 追加したアイテムが別レシピも含め候補から消え、削除すると候補に戻ること。
10. 保存リストを読み込み、変更して上書きした後もリストが重複せず、再ロードで変更が残ること。
11. 未保存状態の切り替えキャンセル、リスト削除の確認・キャンセルが正しく動くこと。
12. 中間素材の階層表示と合算表を照合し、TSVが設定したフォルダーに同じ数量で出力されること。

## v1.0.0.1
基本素材は充足時に緑、中間素材は充足時に青で表示します。判定はバッグ＋リテイナーの取得済み記録と、リスト全体の必要数で行います。未取得のバッグは充足扱いにしません。クリスタル類は基本素材として判定します。ホームに過去の据え置き更新も含む全変更履歴を表示します。


### v1.0.0.1 追加修正
全体不足の正数を赤で表示します。不足素材名にカーソルを合わせると『所持状況を確認』ボタンがフェードインし、クリックでFFXIV標準の所持状況確認を実行します。取得済み記録で不足が確認できる素材に限定し、未取得・充足素材では実行しません。登録人数分のリテイナー記録が揃わない場合と人数未確認の場合は、赤い丸を点滅表示します。ゲーム内の検索結果には本プラグインで集計しない保管場所や収集品も含まれる場合があります。実ゲームでの呼び出し・ホバー操作は未検証です。


背景に薄い紫のハンマーを描画し、約55秒周期で左から右へスライドします。背景は操作を受け取らず、ウィンドウを閉じている間・折りたたみ中は描画しません。追加の画像ファイルは不要です。


不足素材の確認ボタンは、素材名の可視テキストにマウスが重なったフレームで即時表示します（フェードイン待機なし）。ボタンへ移動する猶予は0.8秒、ボタン上では表示を維持します。


### リテイナー記録の取得・リセット
プラグイン有効化時に全キャラクターのリテイナー記録をクリアします。各記録は取得後24時間で期限切れとなり、人数・所持数から除外します。通常・拡大所持品画面を検出し、5ページとクリスタルの読み込み完了と約0.75秒の安定を確認してから記録します。同一リテイナーの再取得では人数を重複加算しません。対象素材を持っていない場合も、全所持品の取得が完了すれば確認済みとして数えます。画面とログに未読込コンテナー等の取得状態を表示します。実ゲームの取得動作は未検証です。


### リテイナー記録の一括確認（v1.0.0.1）
呼び鈴を操作し、ゲームのリテイナー一覧を開いてから、素材リストの「リテイナー記録確認」を押してください。
未確認のリテイナーを選択 → アイテムの受け渡し → 新しい所持品記録の取得を待つ → 所持品画面を閉じる → リテイナーを帰還、の順に全員を確認します。
確認済みのリテイナーはスキップします。アイテムの移動は行いません。
処理中はゲーム側のリテイナー操作をせずにお待ちください。「確認を中止」で以後の自動操作を停止できます（その時点のゲーム画面は残ります）。
各段階で30秒以上応答がない場合やキャラクターが変わった場合は中止します。呼び鈴への移動・呼び鈴を開く操作は手動です。
API 15でビルド確認済み。ゲーム内での巡回動作は実機確認が必要です。

### リテイナーメニュー操作の修正（v1.0.0.1のまま）
メニュー照合をゲームクライアントの言語とSeStringの表示テキストに統一しました。コールバック送信のみでは次へ進まず、所持品画面表示、記録更新、所持品画面閉鎖、一覧復帰を確認します。反映されない操作は2秒間隔で再試行し、30秒の上限で停止します。待機理由とメニュー照合結果をログに記録します。


### セリフ・日本語メニュー対応（v1.0.0.1）
自動確認中は対象リテイナーのTalk画面を800ミリ秒間隔で進め、メニュー表示後に所持品を開きます。帰還のセリフにも対応します。日本語の「アイテムの受け渡し　[預託中：89枠]」のような可変項目と「リテイナーを帰す」を判定します。セリフ操作をログに記録し、中止後は操作しません。


所持状況確認ボタンは、表示中に描画順を前面へ更新します。バージョンは1.0.0.1のままです。


表示名を Artisan's Material Board に変更しました。既存設定を引き継ぐため、DLL名・内部識別名は BuildLists、起動コマンドは /buildlists を維持しています。既存フォルダーへ差し替えて再読み込みしてください。

所持状況確認ボタンは約0.2秒でフェードインし、素材名またはボタンにカーソルがある間だけ表示します。リテイナー一括確認の正常完了後は呼び鈴の一覧も閉じます。中止・エラー時は自動では閉じません。
